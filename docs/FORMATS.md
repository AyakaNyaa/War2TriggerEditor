# Реализованный профиль форматов

Профиль: исходник Game Maker редактора 1.6.1 + приложенные примеры.
Это профиль редактора, не установленная версия War2Combat.
Исторические доказательства и расхождения описаны в AUDIT.md.

## PUD

Секция: `tag[4]`, затем `u32 LE` длина payload, затем сам payload.
Требуется начальная секция TYPE, длина 16, начало payload `WAR2 MAP`.
Границы проверяются до выделения payload; обрезанные секции отвергаются.
Неизвестные секции и повторные секции сохраняются в исходном порядке.
Несколько OILM запрещают запись триггеров из-за неоднозначности.

Байткод располагается в начале OILM.
Изменение программы патчит только её байты; длина OILM и карта не перестраиваются.
Хвост после нового окончания сохраняется из исходных данных контейнера.
Расширение в ненулевые непрозрачные байты после исходной программы блокируется.

## W2TR

`program | optional metadata`

Программа заканчивается командой FE FF или FE ED.
Это распознаётся только на границе команды после полного чтения её аргументов.
Обычный поиск маркера по всему файлу не используется.
Окончание исходного файла сохраняется; новые проекты используют FE ED.

Метаданные: `00 FD`, затем записи до EOF:
`id:u16 LE | name_length:u8 | raw_name[name_length]`.
ID, порядок, дубликаты и кодировка имён сохраняются побайтно.
В текущей версии имена не переименовываются и не нормализуются.
Неизвестные или обрезанные метаданные сохраняются, но редактирование блокируется.
Старый вариант без метаданных также читается и сохраняется без добавления полей.

## Команды

Каталог `schemas/commands/legacy-1.6.1.json` описывает длины команд 0–127.
Окончание 254 обрабатывается отдельно; неизвестный opcode не пропускается наугад.
Список юнитов (6) имеет 28 подкоманд с разными длинами.
37, 120–123 содержат строки переменной длины.
Команда 0 — инструкция выхода, не маркер окончания редакторского контейнера;
данные после неё сохраняются и разбираются до явного окончания.

Базовые правила: баланс IF/end IF, Repeat/end Repeat без вложенных Repeat,
длины аргументов, отдельные известные диапазоны и ограничения текста.
Проверка структуры не доказывает игровую корректность всей программы.
Диапазоны и смысл некоторых продвинутых аргументов ещё требуют уточнения.

Уточнённые расхождения с triggers.txt:
- Сравнение (8): GMK читает `VAL, comparison, VAL, FLAG`,
  а текстовый документ меняет первые два аргумента местами.
- Звук (108): GMK читает `sound:u16, X:u8, Y:u8`, всего 5 байт с opcode.
- FE ED и FE FF поддерживаются как отдельные варианты, без принудительной миграции.

Игровые строки кодируются Windows-1251 с отказом при неподдерживаемых символах.
Незатронутые байты строк не перекодируются.
Применённая пользователем текстовая правка пересобирает только эту команду.

## Надёжность записи

Проверить состояние и исходный хеш → создать и проверить бэкап → записать
временный файл на том же томе → flush → проверить байты → ещё раз проверить
конфликт → заменить целевой файл → проверить итоговый хеш.

Непрерываемую транзакцию между несколькими файлами эта версия не реализует:
PUD и W2TR открываются и сохраняются независимо.
Гарантия против произвольной одновременной записи сторонним процессом ограничена
проверками хешей: некооперативный процесс может попасть в узкое окно между
последней проверкой и заменой. Исключение такого сценария ещё требует доработки.
Поведение при физическом отключении питания отдельно не сертифицировано.

Снимок сеанса записывается через временный файл до изменения состояния в памяти.
Он содержит исходный файл, его хеш, команды и ревизию. Версия снимка — 1.
При восстановлении проверяются версия, хеш и возможность собрать программу.
