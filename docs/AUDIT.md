# Аудит пакета War2 Trigger Edit

Дата: 9 ноября 2026. Источники: приложенный ZIP и извлечённые данные GMK.
Статус: предварительный статический аудит; EXE и Game Maker не запускались.

## Состав и метод

В архиве 21 файл: GMK, EXE, ICO, два LANG, triggers.txt,
четыре PUD, десять W2TR, пояснение к шести примерам.
Состав и SHA-256 зафиксированы в `legacy-audit/manifest.json`.

GMK содержит заголовок версии 800. Извлечены 150 корректно завершающихся
zlib-потоков и 45 скриптов с проверенной длиной записи имени и текста.
Это не полный разбор всех объектов, событий и ресурсов GMK.
В INIT_LANG указана версия редактора 1.6.1; версию EXE этим не подтверждаем.

Основные изученные скрипты: load, save, load_tr, save_tr, trig,
creator, creator6, field_click, INIT_VAR_NAMES, INIT_LANG, GET_LANG.
Результаты воспроизводятся утилитами audit_package.py и inspect_samples.py.
Эти Python-утилиты обслуживают аудит; стек новой программы — Rust + React.

## PUD: установлено по всем четырём файлам

Контейнер последовательно читается как:
`tag[4] + payload_length:u32 little-endian + payload[length]`.
Во всех примерах секции полностью укладываются в длину файла,
неразобранного хвоста после последней секции нет.

| Карта | Размер | Поле DIM | Секций | Размер OILM |
|---|---:|---|---:|---:|
| capture flag v3 | 36 078 | 64×64 | 19 | 4 096 |
| desert strike v4 | 122 430 | 128×128 | 19 | 16 384 |
| edo def v1.4 | 122 886 | 128×128 | 19 | 16 384 |
| hero surv v1.3 | 122 648 | 128×128 | 20 | 16 384 |

Секции: TYPE, VER␠, DESC, OWNR, ERA␠, DIM␠, UDTA, UGRD,
ALOW, SIDE, SGLD, SLBR, SOIL, AIPL, MTXM, SQM␠, OILM, REGM, UNIT.
Дополнительно в hero surv есть ERAX. Символ ␠ обозначает настоящий пробел.
Назначение ERAX здесь не установлено: сохранять побайтно.

triggers.txt сообщает, что War2Mod читает команды из OILM.
Проверка четырёх пар подтвердила: программа W2TR, включая FE FF,
побайтно совпадает с началом OILM соответствующего PUD.
Размеры этих программ: 295, 956, 2 052 и 9 066 байт соответственно.
Это проверка совпадения байтов, а не подтверждение исполнения в игре.

Старый save ищет строку OILM скользящим побайтным поиском,
затем пишет в существующий файл с ограничением размером секции.
Оставшиеся байты OILM после короткой новой программы не очищаются.
Нет структурного поиска секции, резервной копии или атомарной замены.

Для новой реализации: разбирать границы секций; сохранять их порядок,
повторы, неизвестные payload, неиспользованные области и исходные байты.
Поиск четырёх букв внутри произвольного payload недопустим.
Повтор OILM или неоднозначная структура требуют диагностики и запрета экспорта.

## W2TR: установлено по коду и примерам

В save_tr нет файловой сигнатуры и поля версии.
Он сохраняет байткод com, затем `00 FD`, затем записи имён до конца файла.
Окончание программы находится внутри com.

Предварительная структура:
`program including FE FF / FE ED | 00 FD | name records until EOF`.
Запись имени: `id:u16 LE | byte_length:u8 | raw_name[byte_length]`.
INIT_VAR_NAMES создаёт 512 имён; код trig использует 0–255 для VAL,
256–511 для FLAG. Неизвестные ID и исходные байты имён нельзя выбрасывать.

| W2TR | Размер | Смещение FE FF | Записей имён |
|---|---:|---:|---:|
| capture flag | 297 | 293 | 0 |
| desert strike | 958 | 954 | 0 |
| edo def | 2 054 | 2 050 | 0 |
| hero surv | 9 068 | 9 064 | 0 |
| ex/1 | 366 | 109 | 19 |
| ex/2 | 356 | 62 | 19 |
| ex/3 | 217 | 60 | 9 |
| ex/4 | 238 | 67 | 9 |
| ex/5 | 270 | 78 | 10 |
| ex/6 | 213 | 82 | 7 |

Во всех десяти найден один кандидат `FE FF 00 FD`,
после которого записи имён укладываются в EOF без обрыва.
Этот поиск использован только для исследования оболочки.
Рабочий парсер должен распознавать маркер на границе команд:
те же байты могут оказаться внутри текста или числового аргумента.

Критичное расхождение: load_tr разделяет программу и имена только по
`FE ED 00 FD`, а все примеры содержат `FE FF 00 FD`.
Скрипт trig распознаёт FE ED и FE FF, второй помечает как legacy.
PUD load также завершает загрузку на FE ED, а не FE FF.
Следовательно, старый код нельзя переносить без проверки совместимости.

Имена существуют только в W2TR, что прямо отмечено в triggers.txt.
Экспорт только в PUD не может сохранить имена: UI должен сообщать об этом
и предлагать сохранить сопутствующий W2TR. Связь файлов не выводить только из имени.

## Команды и локализация

В trig есть верхнеуровневые команды 0–127 и окончание 254.
Часть команд имеет переменную длину; команда 6 содержит подкоманды.
Значения VAL, FLAG, GVAL и TIMER имеют разное время жизни по triggers.txt.
Условия и повторения требуют структурной проверки.

Есть расхождения документации с кодом:
- Документ описывает окончание FE FF; GMK также поддерживает FE ED.
- Для команды 108 документ перечисляет поля, не укладывающиеся в size 5.
  GMK trig читает sound:u16 из байтов 1–2, X/Y из байтов 3–4, всего 5 байт.
- В конце документа диапазон «124–253 unused» противоречит описаниям 124–126
  и существованию 127 в исходнике.

Нужен каталог команд: длина, аргументы, допустимые диапазоны,
подкоманды, стадия исполнения, источник знания и статус уверенности.
Профиль формата редактора не считать версией игрового движка.
Неизвестную длину команды нельзя угадывать или принимать за один байт:
сохранять остаток как непрозрачные данные и ограничивать редактирование.

Оба LANG содержат 1 006 строк: заголовок и 1 005 позиционных записей.
Оба файла не являются корректным UTF-8. GMK GET_LANG ожидает 1 005 записей.
CP1251 — рабочая гипотеза для русского файла; точную кодировку игровых строк
нужно проверить отдельно. Новый UI — Unicode, переводы с устойчивыми ключами.
Преобразование текста в байты игры — явная проверяемая операция.

## Риски и незакрытые вопросы

| Риск | Решение в проекте |
|---|---|
| Неизвестна целевая сборка War2Combat/War2Mod | Зафиксировать профиль и игру для приёмки |
| Противоречия GMK и описания | Таблица доказательств, дополнительные образцы и проверка в игре |
| Нет примера FE ED и повреждённых файлов | Добавить искусственные негативные образцы; получить реальные новые |
| Маркер встречается в аргументах | Разбор команд, без глобального поиска маркера |
| Хвост OILM может иметь значение | Сохранять хвост, не очищать и не расширять секцию автоматически |
| Программа не помещается в OILM | Отказ от записи, указать требуемый и доступный размер |
| Семантика неизвестной команды неясна | Просмотр и сохранение оригинала; блокировать небезопасное изменение |
| Имена/текст зависят от кодировки | Raw bytes + отображение; запрет тихой замены символов |
| Игра/редактор меняет файл параллельно | Сверка исходного хеша перед записью |
| Неясны права на графику и исходный пакет | Не включать исходные игровые ресурсы в публичный дистрибутив до выяснения |

Побайтный roundtrip новой реализации, изменение команд, восстановление после
сбоя и совместимость в игре ещё не проверены: новая программа пока не написана.
