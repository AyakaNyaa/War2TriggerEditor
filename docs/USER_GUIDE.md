# Работа с конструктором

## Запуск и открытие

1. Распакуйте тестовый выпуск и запустите `War2TriggerEditor.exe`.
   Подробности — в [RUN_RU.md](RUN_RU.md).
2. «Открыть файл» открывает PUD или W2TR с привязкой к пути.
   «Импорт файла» загружает копию; первое сохранение предложит выбрать место.
3. Для чистого W2TR нажмите «Новый сценарий».

Слева расположен компактный список элементов сценария, справа — широкая форма.
«Каталог команд» на верхней панели открывает отдельное окно с группами и поиском.
Условие и действия настраиваются рядом. Кнопка применения находится под формой
и остаётся доступной при прокрутке полей.
Элемент появляется в сценарии после заполнения и нажатия кнопки добавления.
Изменения записываются на диск только кнопкой «Сохранить».

## Цель миссии и условие победы

1. Нажмите «Каталог команд» и найдите «Цель миссии — свой текст».
2. Сразу впишите задание: например, «Уничтожьте войска синего игрока».
3. Нажмите «Добавить настройку».
4. Нажмите «Новый триггер».
5. В блоке «Когда» выберите «Количество юнитов», игрока «Синий»,
   нужный тип юнитов (или любой тип), сравнение «Равно» и количество 0.
6. В блоке «Тогда» выберите действие «Победа».
7. Нажмите «Добавить триггер».

Текст задания описывает цель игроку. Триггер проверяет её достижение.
Сам по себе текст не запускает победу.
Команда «Стандартные условия победы» из исходного редактора
включает штатную проверку уничтожения противников.

## Другие условия и несколько действий

Конструктор поддерживает количество юнитов, количество ресурсов,
ручной переключатель и выполнение без условия.
Например: золото синего игрока не меньше 50 000 → показать сообщение.

«Добавить действие» открывает каталог с поиском и группами. После выбора
сразу появятся параметры действия. Кнопка «Заменить» меняет тип действия;
стрелки рядом с ним меняют порядок. Действия выполняются сверху вниз
внутри одного условия.
Вариант «Без условия» выполняет действия при каждом проходе программы.
Настройки, необходимые до старта миссии, добавляются отдельно в начало.

Для количества юнитов текущий шаблон принимает порог 0–255;
для ресурсов — 0–4 294 967 295. Служебные значения выбираются автоматически.
Если безопасных свободных номеров нет, добавление остановится с объяснением.

## Что означают переключатели

Флаг в логике сценария — переключатель, который запоминает «да» или «нет».
Его номер и его состояние — разные вещи. Например, №7 может означать
«награда уже выдана»:

1. В триггер выдачи награды добавьте действие «Переключатель: задать значение».
2. Укажите №7 и включённое состояние.
3. В другом триггере выберите условие «Переключатель — расширенный режим»,
   тот же №7 и ожидаемое состояние «Включён — да».

В обычных условиях количества юнитов/ресурсов служебные переключатели скрыты.
Ручные номера нужны для связи сложных сценариев. Пояснение и пример
доступны в раскрывающемся примере непосредственно в форме ручного условия.

В старой команде «Получить параметр» слово «Флаги» означало выбор
дополнительных игроков. Здесь цвета выбираются галочками, а нейтральный
и локальный игроки — по названиям. Это отдельный механизм.

## Поиск, группы и порядок

Поиск сверху (Ctrl+K) охватывает каталог и текущий сценарий:
названия, группы, параметры и текст сообщений/задания.
Для совпадений каталога нажмите кнопку с их количеством в строке поиска
или откройте «Каталог команд». В окне каталога есть собственный поиск.
Группы и команды отсортированы по алфавиту текущего языка.
Фокус сразу находится в поиске; стрелка вниз переходит к результатам,
Enter выбирает единственное совпадение, Esc закрывает окно и возвращает фокус.

В списке слева можно выбрать «Порядок выполнения», «По группам» или «По алфавиту».
Это меняет только отображение. Стрелки на карточке перемещают целый блок
и действительно меняют порядок выполнения. Копирование и удаление также
работают с целым условием и его действиями.

«Команды» раскрывает исходные команды и вложенные условия.
Любую раскрытую команду можно нажать и настроить справа.
Ручные открывающие условия/повторы доступны через переключатель каталога
«Ручные блоки условий и повторов» в окне каталога;
закрывающая команда добавляется автоматически.
Произвольные вложенные конструкции сохраняются; конструктор заменяет только
распознанные блоки, которые можно безопасно перестроить.

## Применение, история и сохранение

Кнопка добавления/применения меняет текущий сеанс. Предпросмотр необязателен
и показывает различия перед применением. «Отменить» / «Повторить» работают
с применёнными изменениями. Набранные, но не применённые поля не сохраняются;
при смене элемента редактор предложит их сбросить.

«Сохранить» сначала создаёт и проверяет бэкап, затем записывает временный
файл и заменяет оригинал. Для нового места используйте «Ещё → Сохранить как…».
Сохранение при неприменённых полях блокируется с пояснением.

Рядом с файлом создаётся каталог `.имя-файла.war2-backups`.
«Ещё → Бэкапы файла» позволяет восстановить копию с отдельным подтверждением;
перед заменой создаётся бэкап текущего файла.

После применённой правки создаётся также снимок сеанса в
`%LOCALAPPDATA%/War2TriggerEditor/recovery`.
После перезапуска откройте «Ещё → Снимки восстановления».
Открытие снимка не перезаписывает карту; успешное сохранение удаляет снимок.
Неприменённые поля в снимок не входят.

Если файл изменён другой программой, запись останавливается.
Сохраните правки в другое место или заново откройте актуальный файл.

## Ограничения тестового выпуска

- Неизвестные и неоднозначные данные открываются только для просмотра.
- Размер OILM не увеличивается, остальные секции и неизвестные хвосты сохраняются.
- Игровые строки используют предварительный профиль Windows-1251;
  неподдерживаемые символы отклоняются.
- PUD и внешний W2TR пока открываются отдельно, без автоматической сборки пары.
- Часть продвинутых форм ещё содержит числовые аргументы.
- Игровая совместимость требует проверки в целевой сборке War2Combat/War2Mod.
- AI, ручной текстовый язык и редактор ландшафта в выпуск не входят.
