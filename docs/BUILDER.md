# Семантика исходного редактора и конструктор

## Источники

Повторно разобраны исходный GMK 800 редактора 1.6.1, его меню,
создатели форм, обработчики полей и примеры W2TR/PUD из пользовательского архива.
GML анализируется как данные, без запуска кода исходного приложения.

Восстановлено 125 именованных ресурсов и декларации форм для 128 команд.
Доказательства: `legacy-audit/evidence/` и `legacy-audit/semantics/`.
Метаданные: `schemas/commands/legacy-forms.json`, `legacy-groups.json`,
`form-fields.json`. Меню исходника содержит 13 групп.
Команды 60, 87, 93, 94, 97, 100, 104, 105, 106, 122, 123 отмечены
в `drawer.Create` как необходимые до старта миссии.

Создание метаданных воспроизводится после распаковки исходного архива:

```powershell
python tools/extract_catalog.py
python tools/audit_editor_semantics.py
python tools/build_form_schema.py
python tools/generate_types.py
```

Формы принимаются только при полном покрытии байтов без пересечений.
Динамические формы и битовые наборы, не описываемые декларацией,
сохраняют ручную реализацию или отображаются аргументами.
Типы полей, ширины 1/2/4 байта и варианты выбора определяются на стороне Rust.
React передаёт значения через API и не собирает двоичные команды.

## Текст задания и победа

`120` задаёт собственный текст цели миссии; `2` выбирает стандартный текст.
`24` завершает миссию победой, `25` — поражением.
У `29` нет аргумента выключения: исходник описывает включение стандартной
проверки уничтожения всех противников. Эти команды имеют разные назначения.

Высокоуровневый триггер объединяет проверку и действия.
Он компилируется в существующий формат без новых опкодов или метаданных.

Шаблон количества юнитов:

1. `6/0` — выбрать тип юнитов. По каталогу LU: 107 — любой юнит,
   105 — любое здание, 106 — любое существо, 110 — здание 4×4.
2. `6/2`, характеристика Owner=44 — оставить юниты выбранного игрока.
3. `30` — записать количество во временное значение.
4. `5` — записать заданный порог (0–255).
5. `8` — сравнить значения и записать результат в переключатель.
6. `22` — выполнить действия при включённом переключателе; `23` закрывает блок.

Шаблон ресурсов: `35` (игрок, ресурс, u32-порог, сравнение, переключатель),
затем `22`, действия и `23`. Игрок ресурса — 0–7.
Сравнения: равно, не равно, не меньше, не больше, больше, меньше.

Шаблон ручного переключателя использует `22` или `33` и `23`.
Вариант без условия сохраняет действия непосредственно в программе.
Он не создаёт искусственную группу в двоичном формате.

## Служебные значения

Автоматический подбор консервативен: занятыми считаются все байтовые значения,
встречающиеся в текущей программе и действиях, а также номера 0–15.
Если свободных номеров недостаточно, операция не применяется.
Это предотвращает прямые совпадения с существующими ссылками, но не является
полной моделью косвенного поведения движка конкретной версии игры.

Обратное распознавание использует только точные шаблоны.
Блок с вложенной структурой, совпадением служебных номеров вне блока
или обращением к ним в действиях не заменяется плоским конструктором.
Исходные команды остаются доступны для просмотра и отдельной настройки.
Копия распознанного блока получает новые служебные номера, когда это возможно.

## Два смысла флагов

Логический флаг — запоминаемый переключатель. `21` задаёт состояние,
`22` проверяет включённое, `33` — выключенное. Номер связывает эти операции.
В конструкторе это именуется переключателем с отдельным полем состояния.

В команде `7` поля с флагами имеют другой смысл.
По `creator` и `check_click`: байт 2 выбирает цвета игроков битами 0–7;
бит 0 байта 3 включает нейтрального, бит 1 — локального игрока.
UI заменяет их галочками и четырьмя именованными вариантами.
Биты неизвестных полей не получают выдуманных смыслов.

## API и представление

- `POST /api/v1/commands/draft` возвращает форму ещё не добавленной команды.
- `POST /api/v1/documents/{id}/rules/preview` компилирует/заменяет целый триггер.
- `POST /api/v1/documents/{id}/blocks/preview` копирует, удаляет или двигает блок.
- Применение использует существующий revision-checked `changes/apply`.
- `Program.blocks` содержит диапазоны, вложенность и распознанные условия.

Центральный app-api координирует leaf-крейты через contracts.
Группировка и алфавитный вид не посылают команд изменения и не меняют экспорт.
Сквозной поиск включает каталог и названия/параметры/тексты текущей программы.

Unit-тесты включают независимую модель используемых опкодов для проверки
условия победы. Это структурная и логическая проверка шаблонов;
игровая приёмка в конкретной сборке War2Combat/War2Mod остаётся отдельным этапом.
