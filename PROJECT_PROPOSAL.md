# War2 Trigger Editor — проект на согласование

Статус: одобрено пользователем; реализация начата 9 ноября 2026.
Текущее состояние — в [docs/STATUS.md](docs/STATUS.md).

## Зафиксированные решения пользователя

- Rust + React, Rust workspace с отдельными крейтами.
- «Звезда»: единый API-центр, трактовка подтверждена пользователем.
- Передача данных между компонентами только через явные API.
- Каждый текстовый файл проекта — не более 500 физических строк,
  включая lock-файлы, схемы и генерируемый код. Исключения пользователь отклонил.
- Сначала проект и план, реализация только после согласования.

## Что предлагается согласовать

1. Windows-приложение: Rust + React/TypeScript, оболочка Tauri 2.
2. Единый локальный HTTP API на Axum; оболочка отвечает за окно и запуск.
3. Модульная звезда в одном процессе: крейты функций изолированы,
   центральный крейт организует операции через их публичные API.
4. MVP: безопасное редактирование триггеров в существующих PUD/W2TR,
   русский и английский интерфейс, бэкапы, восстановление, проверка в игре.
5. Полный редактор ландшафта, AI-чат, язык ручного кода и произвольный
   docking — следующие этапы. Базовое изменение размеров панелей входит в MVP.
6. Никаких изменений форматов игры или новых обязательных серверов.

## Ограничения оценки

Аудит подтвердил структуру контейнеров и несколько важных расхождений.
Он не заменяет полную спецификацию команд, новый roundtrip-тест или запуск в игре.
Точная версия War2Combat/War2Mod для приёмки пока не определена.
Это потребуется для проверки совместимости, но не мешает согласовать проект.

Оценка MVP: 31–48 рабочих человеко-дней, включая завершение исследования.
Это предварительная оценка объёма, не обещание календарной даты.
Пересмотр — после этапа спецификации, до расширения объёма реализации.

До фиксации зависимостей проверить совместимость штатного Rust/React toolchain
с лимитом 500 строк для lock-файлов. Допустим только валидный формат,
поддерживаемый инструментами; отключение фиксации зависимостей, архивирование
текстового файла ради обхода лимита или скрытые исключения не допускаются.
Если выбранный набор зависимостей не укладывается, пересмотреть его состав
и архитектурный вариант и вынести конкретное изменение на согласование.

Согласование получено. Результаты реализации и ограничения фиксируются отдельно.
